manageable, containerized system with intelligent routing, health checks, and monitoring.\n\n### Architecture Pattern\n\n**Microservices + Reverse Proxy + Orchestration**\n\n```\nClient Requests\n      ↓\n    NGINX (L7 Load Balancer + SSL Termination)\n      ↓\n   ┌──┴─────────────────────────────────┐\n   │                                    │\n   ↓              ↓            ↓        ↓\n Admin Panel  OpenClaw    LM Bridge   Legacy\n (8004)       (7999)      (8001)      (18789)\n```\n\n### Core Principles\n\n1. **Single Responsibility**: Each service has one clear purpose\n2. **Loose Coupling**: Services communicate via HTTP/APIs\n3. **High Cohesion**: Related functionality grouped together\n4. **Immutability**: Containers are built once, run consistently\n5. **Observable**: Health checks, logs, metrics everywhere\n6. **Resilient**: Automatic restart, health monitoring, fallbacks\n\n---\n\n## ARCHITECTURE LAYERS\n\n### Layer 1: Ingress (Nginx - L7 Load Balancer)\n\n**Port**: 80, 443  \n**Role**: Reverse proxy, SSL termination, routing, compression\n\n**Key Features**:\n- Request routing based on URL path\n- SSL/TLS termination (future: Let's Encrypt)\n- GZIP response compression\n- Health check proxying\n- Long timeout for AI model requests (120s)\n- WebSocket support for real-time features\n- Request/response logging\n- Rate limiting ready (future)\n\n**Routing Table**:\n```\nGET  /api/*         → admin-panel:8002/api     (Backend API)\nGET  /openclaw/*    → openclaw-service:7999    (Skills Orchestrator)\nGET  /lm/*          → lmstudio-bridge:8001     (Model API)\nGET  /dashboard/*   → dashboard-legacy:18789   (Python Dashboard)\nGET  /*             → admin-panel:8004         (React Admin)\nPOST /health        → Nginx internal           (Health endpoint)\n```\n\n### Layer 2: Service Mesh (Docker Network)\n\n**Network**: `synkia-network` (172.25.0.0/16)  \n**Type**: Overlay network\n\n**Features**:\n- Internal DNS resolution (e.g., `openclaw-service:7999`)\n- Service discovery built-in\n- Network isolation from host\n- Custom subnet for IP management\n\n**Services on Network**:\n- `admin-panel` (8004) - React + Node.js\n- `api-backend` (8002) - Express.js API\n- `openclaw-service` (7999) - Skills orchestrator\n- `lmstudio-bridge` (8001) - Model proxy\n- `nginx-proxy` (80, 443) - Reverse proxy\n- `dashboard-legacy` (18789) - Python app\n\n### Layer 3: Application Services\n\n#### Service: Admin Panel (8004)\n\n**Type**: React Frontend + Node.js Backend (Single Container)\n\n**Frontend** (React + Vite):\n- Pages: Dashboard, Docker, Monitoring, Servers, OpenClaw, Tailscale\n- Components: Card, Button, Badge, StatusBadge, Charts\n- State: React hooks + fetch API\n- Styling: Tailwind CSS\n- Charts: Recharts (real-time monitoring)\n\n**Backend** (Node.js + Express):\n- Modules:\n  1. **Docker Manager** - Manage containers, images, stats\n  2. **System Monitor** - CPU, memory, disk, processes, network\n  3. **Server Manager** - SSH to local/remote servers\n  4. **OpenClaw Integration** - Skills management, config editors\n  5. **Tailscale Control** - Serve/Funnel configuration\n  6. **Health Checks** - Service status monitoring\n\n**Exposed Endpoints**:\n- `GET /api/health/all` - Health status of all services\n- `GET /api/docker/containers` - List containers\n- `GET /api/docker/stats` - Container stats\n- `GET /api/system/metrics` - CPU, memory, disk\n- `GET /api/system/processes` - Running processes\n- `POST /api/server/execute` - SSH command execution\n- `GET /api/openclaw/status` - OpenClaw status\n- `GET /api/tailscale/status` - Tailscale status\n\n**Health Check**:\n- Endpoint: `GET /api/health/all`\n- Interval: 30 seconds\n- Timeout: 10 seconds\n- Retries: 3\n- Status: UP if all services pass\n\n#### Service: OpenClaw (7999)\n\n**Type**: Docker container (external image)\n**Role**: Skills orchestrator, LM routing, automation engine\n\n**Purpose**:\n- Central orchestration point for skills\n- IDENTITY, USER, SOUL configuration\n- LM routing and model selection\n- Automation and workflow engine\n\n**Exposed API**:\n- RESTful endpoints for skill management\n- Internal routing to LM Studio (via bridge)\n- Integration with admin panel\n\n**Health Check**:\n- Endpoint: `GET /health`\n- Interval: 30 seconds\n- Timeout: 10 seconds\n\n#### Service: LM Studio Bridge (8001)\n\n**Type**: Node.js proxy service\n**Role**: Forward requests to local LM Studio with cloud fallback\n\n**Purpose**:\n```\nAdmin Panel or OpenClaw\n        ↓\n  LM Studio Bridge (8001)\n        ↓\n    ┌───┴────────────────┐\n    ↓                    ↓\nLocal LM Studio     LM Link Cloud\n(192.168.0.32:1234) (fallback)\n```\n\n**Features**:\n- Proxy to local LM Studio (192.168.0.32:1234)\n- Automatic fallback to LM Link Cloud if local fails\n- Request forwarding: `/v1/models`, `/v1/chat/completions`\n- Timeout handling: 120 seconds for long-running requests\n- Error handling and retry logic\n\n**Health Check**:\n- Endpoint: `GET /health`\n- Tests connectivity to both local and fallback\n- Interval: 30 seconds\n\n#### Service: Legacy Dashboard (18789)\n\n**Type**: Python HTTP service\n**Role**: Backward compatibility\n\n**Purpose**:\n- Maintain compatibility with existing Python dashboard\n- Accessible at `/dashboard/` path\n- Parallel to new React admin panel\n- Gradual migration path\n\n---\n\n## NETWORKING\n\n### Network Topology\n\n```\n┌─────────────────────────────────────┐\n│ Browser Request\n   User clicks button in React\n         ↓\n2. Fetch Request (useFetch hook)\n   GET http://localhost:8004/api/docker/containers\n         ↓\n3. Nginx Routing\n   Matches /api/* → forwards to admin-panel:8002\n         ↓\n4. Backend API Processing\n   Express handler processes request\n   Uses dockerode to get container info\n         ↓\n5. JSON Response\n   Returns [{ id, name, status, ... }]\n         ↓\n6. Browser Rendering\n   React component updates with new data\n   Charts/tables re-render\n```\n\n### Real-time Monitoring Flow\n\n```\n1. useFetchInterval Hook (every 5s)\n   GET http://localhost:8004/api/system/metrics\n         ↓\n2. Backend System Monitor\n   os.cpus() → Calculate usage\n   os.freemem() → Calculate available\n   diskusage → Disk stats\n         ↓\n3. JSON Response with Metrics\n   { cpu: 45.2, memory: 67.8, disk: 52.1, ... }\n         ↓\n4. React State Update\n   useState hook updates metrics array\n   Component re-renders with new data\n         ↓\n5. Recharts Re-render\n   LineChart updates with new data points\n   Animation smooth transition to new values\n```\n\n### OpenClaw Integration Flow\n\n```\n1. Admin Panel\n   GET http://localhost:8004/openclaw/status\n         ↓\n2. Nginx Routing\n   Matches /openclaw/* → forwards to openclaw-service:7999\n         ↓\n3. OpenClaw Response\n   Returns status, skills, models info\n         ↓\n4. Admin Panel Display\n   Skills list, models, configuration editors\n```\n\n### LM Studio Request Flow\n\n```\n1. OpenClaw or Admin Panel\n   POST http://localhost:8001/v1/chat/completions\n   { model: \"neural-chat\", messages: [...] }\n         ↓\n2. LM Studio Bridge\n   Tries to connect to 192.168.0.32:1234\n   If fails → Uses LM Link Cloud fallback\n         ↓\n3. Response\n   { choices: [{ message: { content: \"...\" } }] }\n         ↓\n4. Back to OpenClaw/Admin\n   Continues processing with model response\n```\n\n---\n\n## TECHNOLOGY STACK\n\n### Frontend\n- **Framework**: React 18\n- **Build Tool**: Vite\n- **Styling**: Tailwind CSS\n- **Charts**: Recharts\n- **Icons**: Lucide React\n- **HTTP Client**: Fetch API\n\n### Backend\n- **Runtime**: Node.js 18+\n- **Framework**: Express.js\n- **Docker**: dockerode\n- **SSH**: node-ssh\n- **HTTP**: axios\n- **Utilities**: body-parser, cors, dotenv\n\n### Infrastructure\n- **Containerization**: Docker\n- **Orchestration**: Docker Compose\n- **Reverse Proxy**: Nginx\n- **Networking**: Docker overlay networks\n- **Base Images**:\n  - Node.js: `node:18-alpine` (Admin Panel)\n  - Nginx: `nginx:alpine` (Reverse Proxy)\n  - OpenClaw: `openclaw:latest` (external)\n  - Python: `python:3.10` (Legacy Dashboard)\n\n### Monitoring & Logging\n- **Health Checks**: HTTP endpoints + interval polling\n- **Logs**: JSON structured logs to /logs/\n- **Metrics**: System metrics via Node.js OS module\n- **Status**: Visual status badges in admin panel\n\n---\n\n## DEPLOYMENT ARCHITECTURE\n\n### Build Process\n\n```\nSource Code\n    ↓\n┌─────────────────────────────────────┐\n│  docker-compose build               │\n│  ├─ admin-panel:                    │\n│  │  ├─ Stage 1: npm run build       │\n│  │  └─ Stage 2: npm start           │\n│  ├─ nginx:                          │\n│  │  └─ Copy nginx.conf              │\n│  ├─ openclaw-service:              │\n│  │  └─ Pull openclaw image          │\n│  ├─ lmstudio-bridge:               │\n│  │  └─ Build Node.js service        │\n│  └─ dashboard-legacy:              │\n│     └─ Pull dashboard image         │\n└─────────────────────────────────────┘\n    ↓\nDocker Images Ready\n    ↓\n┌─────────────────────────────────────┐\n│  docker-compose up -d               │\n│  ├─ Create synkia-network           │\n│  ├─ Start all containers            │\n│  ├─ Run health checks               │\n│  └─ Initialize logging              │\n└─────────────────────────────────────┘\n    ↓\nServices Running & Healthy\n```\n\n### Startup Sequence (start-synkia-unified.sh)\n\n```\n1. Pre-flight Checks (10s)\n   ├─ Docker Desktop running?\n   ├─ Ports available (80, 8004, 7999, 8001)?\n   └─ SSH keys present?\n         ↓\n2. Build Phase (2-3 min)\n   ├─ docker-compose build\n   └─ Build only changed images\n         ↓\n3. Start Phase (30s)\n   ├─ docker-compose up -d\n   ├─ Create network\n   └─ Start containers\n         ↓\n4. Health Check Loop (2-5 min)\n   ├─ Poll health endpoints\n   ├─ Retry on failure (max 30 times)\n   ├─ Display status updates\n   └─ Wait for all services UP\n         ↓\n5. Success Message (1s)\n   ├─ All services UP\n   ├─ Admin Panel URL: http://localhost:8004\n   └─ Total startup time displayed\n```\n\n---\n\n## HEALTH & MONITORING\n\n### Health Check Strategy\n\n**Three Levels**:\n\n1. **Container Level** (Docker)\n   ```yaml\n   healthcheck:\n     test: [\"CMD\", \"curl\", \"-f\", \"http://localhost:8004/api/health\"]\n     interval: 30s\n     timeout: 10s\n     retries: 3\n     start_period: 40s\n   ```\n\n2. **Service Level** (HTTP)\n   ```\n   GET http://service:port/health\n   → Returns: { status: \"up\", timestamp: \"2026-03-26T...\" }\n   ```\n\n3. **Application Level** (Dependencies)\n   ```\n   GET http://admin-panel:8004/api/health/all\n   → Returns: {\n       \"admin-panel\": \"up\",\n       \"openclaw\": \"up\",\n       \"lm-bridge\": \"up\",\n       \"backend\": \"up\",\n       \"dashboard\": \"up\"\n     }\n   ```\n\n### Monitoring Metrics\n\n**System Metrics**:\n- CPU usage percentage\n- Available memory\n- Disk usage per partition\n- Network bytes in/out\n- Process count\n\n**Container Metrics**:\n- Container count (running/stopped)\n- Image count and sizes\n- Container CPU/memory usage\n- Container network I/O\n\n**Service Metrics**:\n- Health status of each service\n- Response time for health checks\n- Request count (future)\n- Error count (future)\n\n---\n\n## SECURITY CONSIDERATIONS\n\n### Network Security\n\n1. **Isolation**\n   - Services run on isolated Docker network\n   - No direct host access unless exposed\n   - Internal communication encrypted (future)\n\n2. **Port Management**\n   - Only necessary ports exposed (80, 443, 8004)\n   - Internal ports (8002) not exposed\n   - Nginx acts as single entry point\n\n3. **Firewall Rules**\n   - Nginx enforces SSL/TLS (future)\n   - Rate limiting on API endpoints (future)\n   - CORS configuration for API\n\n### Data Security\n\n1. **Environment Variables**\n   - Secrets in .env file (not in git)\n   - SSH keys stored locally (~/.ssh/)\n   - API keys for LM Cloud in .env\n\n2. **SSH Access**\n   - Ed25519 key pair recommended\n   - Key stored in ~/.ssh/id_rsa\n   - Remote server authentication via keys\n\n3. **API Authentication**\n   - Session cookies for web UI (future)\n   - API tokens for programmatic access (future)\n   - Rate limiting on endpoints (future)\n\n### Container Security\n\n1. **Image Security**\n   - Use official base images\n   - Regular updates of dependencies\n   - Scan for vulnerabilities (future)\n\n2. **Runtime Security**\n   - Read-only filesystem where possible (future)\n   - Drop unnecessary capabilities (future)\n   - Resource limits (CPU, memory)\n\n3. **Secrets Management**\n   - Secrets not in images\n   - Injected at runtime via .env\n   - No logs containing secrets\n\n---\n\n## SCALING STRATEGY\n\n### Horizontal Scaling\n\n```\nBefore:          After (with load balancer):\nClient           Client\n  │                 │\n  └─> Nginx         └─> Load Balancer\n      └─> Admin         ├─> Nginx 1\n          Panel 1       │   └─> Admin Panel 1\n                        ├─> Nginx 2\n                        │   └─> Admin Panel 2\n                        └─> Nginx 3\n                            └─> Admin Panel 3\n```\n\n**How to Scale**:\n\n1. **Multiple Admin Panel Instances**\n   ```yaml\n   services:\n     admin-panel-1:\n       image: synkia-admin-panel\n       ports:\n         - \"8004:8004\"\n     admin-panel-2:\n       image: synkia-admin-panel\n       ports:\n         - \"8005:8004\"\n   ```\n\n2. **Nginx Upstream Configuration**\n   ```nginx\n   upstream admin_backend {\n     server admin-panel-1:8004;\n     server admin-panel-2:8004;\n     server admin-panel-3:8004;\n   }\n   ```\n\n3. **Benefits**\n   - Improved availability\n   - Load distribution\n   - Better performance under load\n   - Rolling deployments\n\n### Vertical Scaling\n\n**Resource Limits** (docker-compose.yml):\n```yaml\nservices:\n  admin-panel:\n    deploy:\n      resources:\n        limits:\n          cpus: '2'\n          memory: 2G\n        reservations:\n          cpus: '1'\n          memory: 1G\n```\n\n### Service-Specific Scaling\n\n1. **Admin Panel**: CPU-intensive (React rendering)\n2. **OpenClaw**: Memory-intensive (skill management)\n3. **LM Bridge**: Network-intensive (model requests)\n4. **Backend API**: I/O-intensive (Docker/SSH operations)\n\n---\n\n## CONCLUSION\n\nThis architecture provides:\n- ✅ **Simplicity**: Single docker-compose file to manage\n- ✅ **Reliability**: Health checks and auto-restart\n- ✅ **Scalability**: Easy to add more instances\n- ✅ **Observability**: Logs, metrics, health status\n- ✅ **Maintainability**: Clear separation of concerns\n- ✅ **Extensibility**: Easy to add new services\n\nFor more details, see:\n- **README.md**: Quick start and overview\n- **DEPLOYMENT_GUIDE.md**: Operational procedures\n- **docker-compose-unified.yml**: Service definitions\n- **nginx/nginx.conf**: Routing configuration\n\n---\n\n**Document Version**: 1.0.0  \n**Last Updated**: 2026-03-26  \n**Status**: Production Ready ✅\n"
